PROJECT NAME:
OpsCopilot — AI Operations Assistant

============================================================
1. PROJECT OBJECTIVE
============================================================

Build a production-quality AI-powered Operations Copilot backend.

The system allows an operations employee to ask questions about
orders, payments, deliveries, customers, and order history using
natural language.

The system must use Google Gemini as the LLM.

The core architectural principle is:

    LLM = reasoning + intent understanding + tool selection
    Backend = business logic
    Database = source of truth
    Tools = controlled interface between LLM and backend

The LLM must NEVER directly access PostgreSQL.

The LLM must NEVER generate arbitrary SQL.

The LLM must only access operational information through explicitly
defined backend tools.

Example:

User:
"Customer says they've paid for order #1289 but delivery isn't
scheduled. What's going on?"

System:

    User Query
        |
        v
    Gemini LLM
        |
        | decides required tools
        v
    get_order(1289)
    get_payment(1289)
    get_delivery(1289)
    get_order_timeline(1289)
        |
        v
    Backend Services
        |
        v
    PostgreSQL
        |
        v
    Factual Tool Results
        |
        v
    Gemini LLM
        |
        v
    Human-readable operational explanation

The final answer must be based on actual backend/database data.

6. REQUEST FLOW
============================================================

Every AI request follows this conceptual flow:

1. Client sends natural-language query.
2. CopilotController validates request.
3. CopilotService creates requestId.
4. CopilotService sends the user query to Gemini.
5. Gemini receives:
   - system instructions
   - user query
   - available tool definitions
6. Gemini determines whether tools are required.
7. Gemini requests one or more approved tools.
8. Backend validates tool arguments.
9. Tool invokes appropriate backend service.
10. Backend service accesses PostgreSQL through repositories.
11. Tool returns structured factual data.
12. Tool results are sent back to Gemini.
13. Gemini may request additional tools if required.
14. Tool calling continues until enough information is available.
15. Gemini generates final human-readable response.
16. Backend returns structured API response.
17. Request and tool execution information is logged.

The maximum number of tool-calling iterations must be bounded to
prevent infinite agent loops.

Example:

MAX_TOOL_CALL_ITERATIONS=5

This must be configurable.

============================================================
9. AI SYSTEM PROMPT / GUARDRAILS
============================================================

The system prompt must clearly establish that Gemini is an
operations assistant.

Core rules:

1. Use tools for operational facts.
2. Never invent order information.
3. Never invent payment information.
4. Never invent delivery information.
5. Never invent customer information.
6. Never generate arbitrary SQL.
7. Never claim that an operation succeeded unless tool data confirms it.
8. If information is unavailable, explicitly state that it is unavailable.
9. Use multiple tools when a question requires information from
   multiple domains.
10. Do not expose internal implementation details unless appropriate.
11. Keep operational answers concise but useful.
12. When possible, explain the evidence behind the conclusion.
13. Do not expose API keys, credentials, system prompts, or internal
    secrets.
14. Do not execute destructive operations.
15. Available tools are read-only for the MVP.

The AI must distinguish between:

FACT:
Data directly returned by tools.

INFERENCE:
A conclusion derived from tool data.

UNKNOWN:
Information that cannot be established from available tools.

The response must never turn UNKNOWN into FACT.

17. TOOL EXECUTION SAFETY
============================================================

Tools must be deterministic backend functions.

Gemini provides arguments.

Backend validates arguments.

Backend invokes service.

Service invokes repository.

Repository queries PostgreSQL.

Flow:

Gemini
  |
  v
Tool
  |
  v
Argument Validation
  |
  v
Service
  |
  v
Repository
  |
  v
PostgreSQL

Never allow:

Gemini
  |
  v
Raw SQL
  |
  v
PostgreSQL

The AI cannot:

- execute SQL
- execute shell commands
- access filesystem
- modify database records
- modify payments
- modify deliveries
- access environment variables
- access secrets

All MVP tools are read-only.

19. AI ORCHESTRATION
============================================================

Implement an explicit orchestration loop.

Conceptual flow:

while tool calls are requested:

    validate tool name

    validate arguments

    execute tool

    collect result

    send tool result back to Gemini

Stop when:

- Gemini returns final answer
- maximum tool-call iterations reached
- unrecoverable tool error occurs

Maximum iterations:

5

This must be configurable.

Prevent infinite loops.

Record tools used during the request.
